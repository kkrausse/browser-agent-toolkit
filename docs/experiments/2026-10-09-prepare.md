# Prepare: image, guest dependencies, precompiled modules (2026-10-09)

What `bat-image` and `bat-prepare` do on diesel2 (12 cores), measured. Format and
conventions: `docs/design/image-format.md`. Decisions: `docs/design/decisions.md`.

## One command

```sh
crates/bat-prepare/prepare-todo.sh [out-dir]      # default target-prepare/prepared/todo
```

It builds `bat-prepare` (release) and runs

```sh
bat-prepare app examples/todo-app -o <out> \
  --opencode <dir with server.js + tree-sitter wasm> \
  --source src --source vite.config.ts --source react-router.config.ts \
  --source tsconfig.json --source package.json
```

Output: `<out>/manifest.json`, `<out>/image-<hash16>.batimg`,
`<out>/program-opencode-server-<hash16>.js`; scratch and cache in `<out>.work/`.

Other subcommands: `pack <dir>[=<sub/path>]... --root <guest path> -o <out> [--verify]`,
`deps <app> --work <dir>` (guest tree only), `info <image> [path]`, `list <image>`,
`cat <image> <path> [--compiled|--facts]`, `policy`.

## Machine state

Other agents were compiling in the same worktree for the whole session. The first set
of end-to-end numbers was taken while the machine was comparatively quiet; the last set
with a load average of 62–71 on 12 cores. Both are given; treat the loaded ones as an
upper bound, not as the cost of the tool.

## Guest dependency tree

Old example (standalone app with its own `bun.lock`, toolkit packages as `file:`):

| | Files | Symlinks | Bytes |
| --- | --- | --- | --- |
| Installed with substitutions, before prune | 10,780 | 603 | 280.5 MB |
| After prune | 10,258 | 566 | 169.3 MB |

Removed: 14 packages (8 platform-native: `@esbuild/linux-x64`, 2 × `lightningcss-linux-x64-*`,
2 × `@rollup/rollup-linux-x64-*`, 2 × `@tailwindcss/oxide-linux-x64-*`,
`@napi-rs/lzma-linux-x64-gnu`; `@types/*` × 5 incl. `@types/estree`; `bun-types`),
10 files (2 stray `.node`, 8 byte-identical copies of OpenCode application files inside
the toolkit package = 60.6 MB), 32 dangling links.

New example (`examples/todo-app`, member of this repo's Bun workspace):

| | Files | Symlinks | Bytes |
| --- | --- | --- | --- |
| Host workspace store (`node_modules/.bun`, no substitutions) | 31,603 | | 324.0 MB |
| Relocated for the app, substitutions applied, before prune | 14,389 | 731 | 186.9 MB |
| After prune | 13,890 | 447 | 173.8 MB |

288 of 417 store packages are reachable only from other workspace members
(the toolkit's build-time dependencies) and are dropped during relocation; prune then
removes 9 packages (3 native, 5 `@types/*`, `bun-types`) and 279 dangling links.

Substitutions applied in both: `esbuild → esbuild-wasm@0.28.2`,
`rollup → @rollup/wasm-node@4.63.1`, `lightningcss → lightningcss-wasm@1.32.0`,
`@tailwindcss/oxide-wasm32-wasi@4.3.3` from its registry tarball; each checked for its
wasm payload. A `dir:` substitution (local shim package) was exercised with a dummy
`esbuild` package and installs at `.bun/esbuild@file+.bat-shims+esbuild`.

Kept although probably unused: `.map` (22 MB in the old tree), `.md`/`.mdx` (4.6 MB),
`.d.ts` (17 MB; `tsc` reads these). Not pruned without a guest file-access trace.

anything in a browser.

## Timings, end to end (`bat-prepare app`)

Old example, quieter machine, forced rebuild, n = 4: **2.3, 2.7, 2.8, 2.5 s** total.
Typical split: Bun installs 0.3 s, prune 0.4–0.55 s, module transform 0.9–1.25 s
(5,249 modules including the 27.7 MB OpenCode bundle), body writes 0.10–0.15 s,
sha256 of the image 0.15 s, program script 0.03–0.18 s.

New example, load average 62–71, forced rebuild, n = 5: **10.2, 7.5, 9.1, 9.9, 8.8 s**
(install 1.2–2.1 s, prune 0.3–1.1 s, transform 2.5–4.9 s, write 0.3–0.7 s, sha256
0.3–0.7 s). The same example earlier under lighter load: 6.1, 6.0, 7.1 s. No quiet-machine
figure exists for the new example.

| Case | Time |
| --- | --- |
| Unchanged inputs (image reused, manifest unchanged), n = 5 | 1–10 ms inside the tool, 0.01–0.07 s wall |
| Source-only change (`src/` edit, or a `scripts` edit in package.json) | 3 ms; image reused, only `manifest.json` rewritten |
| Dependency, lock, policy, OpenCode files, linked workspace package files or tool binary changed | full rebuild as above |

The Bun cache was warm for every run (Bun used its global cache); install time on a
machine with an empty cache was not measured.

## Not done

- Resolution table (section id 1): reserved, not written.
- A program script for Vite's startup module set: the mechanism takes any module list
  (`programs` in the policy, real symlink-free guest paths), but the list needs a loader
  trace.
- Source maps for lowered TypeScript/JSX modules are not stored.
- No compiled-body cache between rebuilds; the whole tree is retransformed (about 1 s
  unloaded).
