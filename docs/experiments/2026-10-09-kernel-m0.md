# Kernel M0 (2026-10-09)

Milestone M0 of `docs/design/rust-rewrite.md`: the kernel Wasm is shared by ≥ 3 workers in
Chrome, the image of the TODO guest tree mounts from OPFS, and `bench/` reports mount time
and 40,000 mixed stat/read calls from two workers at once. Met; numbers below.

## Setup

- diesel2, 12 cores, headed Chrome 154 on Xvfb, driven by `browser-control`.
- **The machine was busy with other builds the whole time** (load average 20–35 on 12
  cores). Earlier runs of the same code at load 35 were 2–3× slower than the table below
  (taken at load ≈ 20). Treat every figure as an upper bound; re-measure on a quiet machine
  before quoting them as final.
- Kernel: `crates/bat-kernel`, `wasm32-wasip1-threads`, stable Rust 1.99, 245 KiB wasm
  (commit `fd190a8`; the working tree's build also contained another agent's uncommitted
  resolver module, which these calls do not touch).
- Tree: `browser-agent-toolkit/examples/todo-app/node_modules` (Bun isolated linker):
  10,415 files, 1,264 directories, 518 symlinks, 195.5 MB, packed by `bat-prepare pack`
  into one 197.0 MB image (12,197 entries, 1.46 MB head).
- Reproduce: `bench/pack.sh`, `crates/bat-kernel/build.sh`, `bun bench/server.ts 4101`,
  `bun bench/run.ts --runs 5 --fresh`. Page: `bench/kernel-bench.html`.
- n = 5 page loads; the first downloads the image, the other four reopen. Median (min–max).

The mixed workload is, per four calls, one whole-file read of a file ≤ 64 KiB, one stat
of an existing file and two stats of missing paths (so two thirds of the stats miss). Misses
are shaped like resolver probes: a wrong extension beside a real file, a missing
`node_modules` directory inside a real package, a package that does not exist. Hit paths are
104 bytes long on average, nine components deep. "µs/call" is each worker's own elapsed
time over its own calls; "wall" is the page's clock around both workers.

## Spike (step 1)

`bench/spike.html`: the page and four workers each do 500,000 lock/increment/unlock rounds
on a plain counter and insert/remove 20,000 keys in a `BTreeMap` behind the same Rust lock;
a fifth worker blocks in the kernel until the page wakes it. Totals exact (2,500,000 and
50,000), six distinct thread ids, the blocked worker stayed blocked until woken (0.4 ms
after the wake). 60–90 ns per contended locked increment.

## Functional check in Chrome

`bench/kernel-test.html` (then `?phase=2` after a reload), all passing:
image symlink + realpath + readdir + stat from the page; image body read from the page
through the kerneld proxy; overlay write/read; recursive watch events; spawn with stdio
pipes, cwd, env and exit status; `waitpid`; the page connecting to a listener opened by a
guest process and exchanging bytes over a kernel socket; SIGKILL of a process blocked in a
kernel read (status 137); a child writing the shared overlay; whiteout and patched file
over the image; `flush()`; after reload, the overlay restored from a snapshot plus later
journal frames, with the non-persistent root empty. A reload while the previous document
still held the Web Lock produced the "already open in another tab" error before the retry
window and `pagehide` release were added, which is the only evidence the lock refusal works;
a real second tab was not tested.

## Where the time goes now

- A raw `bat_stat` export call on a 104-byte path costs about 0.3–0.5 µs in the kernel
  (measured on the page under load). The rest of a 1 µs stat is JavaScript: copying the
  path string into shared memory (~0.3 µs; `TextEncoder.encodeInto` refuses shared
  buffers in Chrome, so it is a `charCodeAt` loop) and building the result object.
- Small reads are dominated by allocating the result: `Uint8Array.prototype.slice` on a
  shared buffer costs several µs for 3 KB; reading into a pooled buffer is 3× cheaper.
  The Node `fs` layer should pool like Node's `Buffer` does.
- Before the image path table, the same stat cost 1.4–1.9 µs in the kernel (a binary search
  per component). With it a path wholly inside the image is one hash and one compare.

## Not measured / not done

- No run on an idle machine; no run with more than two bench workers recorded.
- Download speed is from localhost without transport compression; it says nothing about
  a real network.
- The image cache has no eviction; reading the whole tree would hold 197 MB.
- HTTP/1.1 codec and WebSocket framing are not implemented. A resolver module is being
  written in this crate by the node-runtime agent (`crates/bat-kernel/src/resolve.rs`,
  uncommitted at the time of writing); it is not part of these measurements.
