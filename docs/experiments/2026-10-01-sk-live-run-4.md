**Verdict: the data supports the hypothesis.**

- Open is 2.0× slower controlled (median 72.5 s against 36.3 s); switch is 4.1×
  slower (106.9 s against 25.9 s). Every controlled sample was slower than both
  uncontrolled neighbours.
- Machine load does not explain it. Sample 3 U started at load 8.4 and switched in
  26 s; sample 6 C started at load 4.4 and switched in 96–100 s.
- What matters is the control state when the kernel worker is created, not the
  page's current state. Every switch in both arms started with the page controlled
  (the boot registers the worker and the page is claimed during it).
- The same split appeared without any reload: in the first page load, the first
  kernel (created uncontrolled) switched in 15.4–17.2 s; after Exit and Open editor
  in the same page, the second kernel switched in 60.1–64.7 s. This is the "13 s
  early, 55–64 s later" of run 3. Only the first kernel on a fresh origin is fast.
- In a controlled kernel every guest-side stage is slower by 4–5×, not one stage:
  process start to listen, guest HTTP (session export 0.9–2.6 s per session against
  about 0.3 s), and OpenCode readiness, where the 3 s health probe times out one to
  seven times. Chat was slower too: "Sending…" lasted 11–14 s against about 3 s.
- A cold kernel's first Vite start costs about 10 s to listen and 7 s to connect in
  both arms, so that part of reopen is not the service worker.
- The mechanism is still unknown. This run measured the effect, not its cause.

Two things the data cannot separate:

- Both arms drifted after sample 1: uncontrolled switches went from 18.5 to 26 s
  and controlled ones from 55–74 s (earlier in the session) to 96–123 s. Origin
  storage usage rose from 94.7 MB to 100.7 MB between samples 1 and 2. The cause was
  not identified.
- Sample 2 C coincided with the highest load and main-thread stalls of up to 1.4 s;
  its two switches are the slowest in the run.

## Defects and surprises

- **Every kernel after the first is slow.** Exit then Open editor in the same page,
  or any reload, gives a kernel that switches in 55–123 s instead of 15–26 s.
  Repro: fresh origin, Open editor, switch (fast); Exit, Open editor, switch (slow).
- **Queued send withdrawn by a stray edit.** Repro not found: one of five queued
  sends; `, ` appeared in the composer 126 ms after Enter and vanished 2.2 s later.
- **Transcript flicker while a long answer runs.** Repro: new chat, ask for a
  600-word essay, sample the transcript's text length every 20 ms. No answer text
  was visible for 32 s; then the length oscillated between 117 and 406 characters
  with "Loading earlier messages…" appearing repeatedly. The 2.3 k characters only
  stayed on screen after Stop.
- **Composer reads Ready before the answer is drawn.** Repro: in a controlled
  kernel send a short follow-up; the status was Ready/idle at +15.6 s and the user
  message and answer rendered about 1.5 s later.
- **Shell request without a permission prompt, 125 s.** Repro: ask the agent to run
  `echo R4-SHELL-OK`; it used `runJavascript`.
- **Name field shows "Current workspace" while startup has not finished.** Repro:
  open in a second tab while another owns the workspace, or reopen over an
  interrupted switch; the select shows the real name.
- **Each New chat leaves a session**, even when nothing is sent. Repro: New chat,
  type, Enter, Cancel send; the session list gains an untitled entry.
- **Session order and ids change after every switch restore.**
- **Kernel target lingered after the SQLite case's first step**: still listed 3 s
  after close with the lock free (run 1 saw this; runs 2 and 3 did not).
- **A force exit is recorded with status `ok`** although both of its stages failed.

## Still unverified

- The mechanism behind the service-worker slowdown, and whether creating the
  kernel before the page is controlled, or bypassing the worker, removes it.
- Why both arms slowed after the first sample.
- A permission prompt, the unsupported-form path, "execution state unknown", and
  the chat Retry control.
- A hang from a real guest process; this one was injected at the handle.
- "Retry interrupted switch" on this head (run 3 covered it); `Retry exit` on this
  head.
- `LongCat 2.5 Preview Free`, and any paid model other than Muse Spark 1.3.
- Whether the stray composer edit came from outside the page.
- The guest's `/api/model` returned an empty list once before any session existed;
  not re-checked.
- Forced close through unmount, crash recovery, quota exhaustion, close with a
  SQLite request in flight.
