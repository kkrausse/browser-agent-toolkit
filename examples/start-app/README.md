# Full-stack example: TanStack Start with an Effect API

The TODO app a third time, so the examples compare, but full-stack, and still entirely in
the browser tab: one dev-server process renders the pages on the server, serves the API and
keeps the list in a SQLite file. `../terminal-app` is the page around it (the app in a frame,
the OpenCode terminal agent beside it).

| | |
| --- | --- |
| Routes, loaders, server rendering | TanStack Start 1.168.61 (`@tanstack/react-router` 1.170.42), React 19.3.0, file-based routes with a generated, typed route tree |
| API | Effect 4.0.3, `effect/rpc`: one contract, handlers as Effects over services and layers, a client derived from the contract |
| Database | `node:sqlite` (`DatabaseSync`), `data/todos.sqlite` in the project directory |
| Build | Vite 7.3.6, `@vitejs/plugin-react` 5.2.0, Tailwind 4.3.3, TypeScript 5.9 strict |

## Run

```sh
# repository root: build everything, prepare, serve on http://127.0.0.1:4320 (PORT)
bun run fullstack
# another terminal: the scripted model, told which file has the heading
SCRIPTED_FILE=/workspace/src/routes/index.tsx bun examples/terminal-app/mock-model.ts
```

Open `http://127.0.0.1:4320/` in Chrome. It is `bun run terminal` with another app
(`BAT_APP=examples/start-app`), so the same prerequisites and page parameters apply
(`../terminal-app/README.md`): `?model=<base URL>` for a real endpoint, `?reset=1` to forget
this browser's workspace, which here includes the database. Type
`set the heading to "Tasks"` into the terminal: the agent reads and edits
`src/routes/index.tsx` and the app updates without a reload.

Without the browser runtime, on Node 24: `bun run dev` in this directory (`PORT`, default 5273).

## The files

| File | Lines | What it is |
| --- | --- | --- |
| `src/api/contract.ts` | 25 | The contract: the `Todo` schema, the `TodoNotFound` tagged error, and the `TodoRpcs` group (`ListTodos`, `AddTodo`, `ToggleTodo`, `DeleteTodo`) with payload, success and error schemas |
| `src/api/client.ts` | 34 | The client derived from the contract. `api(client => client.ToggleTodo({ id }))` resolves to a `Result`: the declared value, or one of the declared errors |
| `src/server/database.ts` | 23 | `Database`, a service: the SQLite connection, opened and closed with its layer |
| `src/server/todo-repo.ts` | 47 | `TodoRepo`, a service over `Database`: the only module that knows the table |
| `src/server/handlers.ts` | 16 | One handler per procedure, each an Effect over `TodoRepo` |
| `src/server/http.ts` | 20 | The group as one `Request -> Response` function (`RpcServer.layerHttp`, ndjson) |
| `src/routes/api/rpc.ts` | 7 | The server route that hands every POST to it |
| `src/routes/index.tsx` | 70 | The page: a loader that lists, three mutations, and a `switch` over the error union |
| `src/routes/__root.tsx`, `src/router.tsx` | 34 | The document and the router |
| `src/routeTree.gen.ts` | 86 | Generated by TanStack Router from `src/routes`; rewritten when a route is added |
| `vite.config.ts` | 17 | The plugins; `browserEditor()` first |
| `terminal-app.json` | 6 | What `../terminal-app` needs to know: title, the source the agent may edit, the two recordings |

Types come from the schemas and the route tree, nowhere else: `Todo` is `typeof Todo.Type`,
the handlers are checked against the group, the client's methods and errors are the
group's, and `Route.useLoaderData()` is the loader's return type. `bun run typecheck`
(`tsc --noEmit`, part of the root `bun run typecheck`) is clean with no `any`. Classes
appear only where Effect's own form is one: the tagged error, the two services, the group.

**One process.** The API is not a second server. `src/routes/api/rpc.ts` is a Start server
route, so `POST /api/rpc` is answered by the same dev server that renders the pages. In the
browser the client posts there (under the app's base path). While a page is rendered on the
server the same client is used, but its request goes straight to the handler
(`FetchHttpClient.Fetch` is replaced), with no socket in between. `createIsomorphicFn`
keeps that half, and `node:sqlite` with it, out of the browser's bundle. Start's
`createServerFn` is not used.

**The typed error.** `ToggleTodo` and `DeleteTodo` declare `TodoNotFound`. Tick a todo
that was deleted elsewhere (another tab, or the agent) and the page shows that branch:
"… no longer exists: it was deleted somewhere else." `RpcClientError` is the other member
of the union: the call never reached the server.

## What running in the tab needed

Nothing was missing from the runtime: Start's dev server, its server-side module runner,
Effect and `node:sqlite` ran as they are. What it took is in `vite.config.ts` and the
repository's root:

- `browserEditor()` comes **before** `tanstackStart()`. In the tab it sets Vite's `base` to
  the preview's path (`/preview/5173/`), and Start reads `base` while it is configured to
  derive the router's basepath and the URLs the server renders. In the other order the
  server answered 404 for its own base.
- One `lightningcss` in the workspace (`overrides` in the root `package.json`). Start's
  plugin asks for `^1.33`, Tailwind 4.3.3 pins `1.32.0`. With both installed, Bun's isolated
  linker gave the Start plugin its own instance of Vite, its `instanceof` check of the server
  environment failed and no server rendering was installed ("Cannot GET /"). The guest's
  replacement of lightningcss also stands for one version only.
- `@import 'tailwindcss' source('.')` in `src/style.css`: Tailwind scans `src/`, not the
  project directory, which holds the database.

Known costs: the page is server-rendered, so it shows before it responds; what is typed
into it before React has hydrated is lost (a few seconds on a first open, see the numbers
in `docs/design/decisions.md`). Start's compiler parses every module whose text contains
`.handler(`, dependencies included; the prebundled `effect/rpc` is one, 0.7 s natively at
the first request after each start.

## Recordings

`startup-modules.json` (what the dev server had loaded when the app showed: 1,061 modules)
and `editor-startup-order.txt` (what that start read from the dependency image: 1,349
files, 27 MB) are recorded from a real first open by `../terminal-app/record.ts`:

```sh
# with `bun run fullstack` serving on 4320, in examples/terminal-app
BAT_APP=../start-app bun record.ts --port 4320
```

Both only cost speed when stale. Record them again after a dependency upgrade, then run
`bun run fullstack` again.
